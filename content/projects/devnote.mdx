# 🗂️ DevNote — 개발자 정보 관리 대시보드

> **서버·DB·API 접속 정보부터 메모·문서까지, 개발에 필요한 모든 정보를 한 곳에서 관리하는 IndexedDB 기반 로컬 웹 앱**
> 데이터는 브라우저에만 저장되며, 카드 본문·태그·폴더명은 패스프레이즈로 at-rest 암호화할 수 있습니다. AI Smart Paste(공유 키 또는 Anthropic·Gemini·OpenAI BYOK), 카드 전체 찾기/바꾸기, txt·md 가져오기와 md 내보내기, 옵트인 Google Drive zero-knowledge 동기화(실험)를 지원합니다.

## ✨ 핵심 구현 내용

### 1. 🗄️ 5종 카드 타입 시스템
개발에 필요한 정보를 체계적으로 분류·관리할 수 있는 카드 기반 시스템을 설계했습니다.
- **Server**: 서버 접속 정보 (host, port, username, password, SSH key)
- **DB**: 데이터베이스 연결 정보 (host, port, dbName, credentials)
- **API**: API 엔드포인트 정보 (url, method, apiKey, token, headers)
- **Note**: 자유 텍스트 메모 (v1.3.0에서 Markdown 타입을 Note로 통합·마이그레이션)
- **Document**: 다중 섹션 복합 문서 (5종 섹션을 자유롭게 조합)

### 2. 📄 Document 카드 — HybridContent 아키텍처
하나의 문서 안에 접속 정보 + URL + 환경변수 + 코드 + 메모를 섹션 단위로 조합할 수 있는 복합 문서 시스템을 구현했습니다.
- **5종 섹션**: Markdown, Credentials, URLs, Env, Code
- **DnD 섹션 정렬**: `@dnd-kit/sortable`로 드래그 앤 드롭 순서 변경
- **섹션별 접기/펼치기**: SectionWrapper 공통 헤더로 통일된 UX
- **섹션별 Smart Paste**: 각 섹션 타입에 맞는 텍스트 자동 파싱

### 3. 🤖 AI Smart Paste — 공유 키 + 멀티 프로바이더 BYOK
초기에는 정규식(Tier 1) + Claude API(Tier 2) 2단 구조였으나, 정규식 경로의 오탐·유지비 대비 효용이 낮아 v1.2.1에서 **AI 단일 호출**로 전환했습니다.
- **공유 키 모드**: 키 없이도 사용 가능 — Vercel Edge Function 프록시 경유, IP당 하루 20회 제한
- **BYOK 멀티 프로바이더**: Anthropic(Claude Sonnet) · Google(Gemini Flash) · OpenAI(GPT-4o 계열) 중 선택, 키는 IndexedDB가 아닌 **세션 메모리에만** 보관
- **구조화 추출**: `tool_use` + `tool_choice`로 카드 필드 스키마를 강제해 자유 텍스트 → 카드 필드 자동 매핑
- **Document Smart Paste / 콘텐츠 요약**: 자유 텍스트 → Section[] 구조화, 카드 내용 → 핵심 요약 + 키포인트

### 4. 💾 로컬 우선 데이터 아키텍처
AI 호출과 옵트인 동기화를 제외하면 데이터가 브라우저 밖으로 나가지 않는 구조입니다.
- **Dexie.js (IndexedDB)**: 스키마 v21까지 단계적 마이그레이션, `useLiveQuery` 반응형 쿼리
- **File System Access API**: Chrome/Edge 네이티브 파일 저장 + Firefox `<input>` 폴백
- **JSON 백업/복원**: 전체/선택 내보내기, Append/Replace 가져오기 (2-Pass 폴더 리매핑)
- **자동 백업 알림**: 7일 경과 또는 미백업+10건 이상 시 toast 알림

### 5. 🔍 검색 & 필터 시스템
- **Fuse.js 퍼지 검색**: 제목, 태그, 콘텐츠 통합 매칭
- **타입/태그 필터 조합**: 카드 타입별 + 태그별 필터링
- **폴더 트리 네비게이션**: 계층 구조 탐색 + DnD 이동

### 6. ✏️ 에디터 & UX
- **CodeMirror 6**: JSON · SQL · JS/TS · Python · YAML · HTML · CSS · Dockerfile 언어 모드
- **탭 기반 다중 편집**: 동시 여러 카드 편집, Ctrl+S 저장
- **다크/라이트 테마**: 즉시 전환
- **커스터마이징 가능한 단축키**: 새 카드 `Mod+Alt+N`, 검색 `Ctrl+K`, 탭 닫기 `Mod+Alt+W` 등 16종 명령 재지정 + 커맨드 팔레트(`Mod+Shift+P`)
- **우클릭 컨텍스트 메뉴**: 이름 변경, 삭제
- **사이드바 접기/펼치기**: hover 핸들로 복원

### 7. 🔐 다층 보안 — at-rest 암호화 · 암호화 백업
- **at-rest 암호화**: AES-GCM + PBKDF2(100k)로 카드 본문 암호화(v1.6.0), v1.9.1부터 태그·폴더명·탭 드래프트까지 확대. 목록·검색을 위해 제목만 의도적으로 평문 유지
- **암호화 백업**: salt·반복 횟수를 담은 봉투(envelope) 포맷으로 백업 파일 암호화, 가져올 때 암호화 여부 자동 감지(v1.7.0)
- **트랜잭션 원자성**: 암호 연산을 먼저 끝내고 쓰기만 트랜잭션에 넣는 compute-then-write, 추가 전 암호화(encrypt-before-add), 카나리 값으로 패스프레이즈 검증

### 8. ☁️ BYO-storage zero-knowledge 동기화 (실험)
- 자체 서버·계정 없이 사용자의 Google Drive `appDataFolder` 권한(`drive.appdata`) 하나만 사용
- **DEK/KEK 구조**: 무작위 DEK를 패스프레이즈 유래 KEK(PBKDF2 600k)로 감싸, 패스프레이즈 변경 시 DEK 재포장만으로 처리
- 노트별 `{uuid}.enc` 파일 + manifest tombstone으로 삭제 부활 방지, 충돌은 LWW + 충돌 사본, 버전 지문은 DEK 기반 HMAC-SHA-256
- Google 로그인이 자동화를 차단해 실계정 왕복을 E2E로 검증하지 못했으므로, UI에 **"실험" 배지**로 한계를 명시

### 9. 🔎 카드 전체 찾기/바꾸기 (v2.1.0 → v2.2.2)
- `@codemirror/search` 기반 Ctrl+F / Ctrl+H, `literal` 모드로 `C:\temp` 같은 경로를 입력 그대로 검색
- 에디터 단위가 아닌 **앱 레벨에서 카드 데이터를 평탄화(flatten)** 해 섹션을 넘나드는 매치 카운터 제공, 모두 바꾸기는 타깃별 뒤에서 앞으로 적용
- 비밀번호·secret 값은 평탄화 단계에서 제외해 검색·치환 경로 어디에도 노출되지 않음
- `data-search-path` DOM 계약을 SSR 렌더 테스트로 양방향 기계 검증

### 10. 📥 파일 가져오기·내보내기 · UX 표준화
- txt·md 단일 파일 가져오기 + 화면 전역 드래그 앤 드롭(depth 카운터로 오버레이 잔존 방지), `.json` 드롭은 전체 교체 경로 차단을 위해 거부
- md 내보내기를 전 카드 타입·4개 진입점으로 확장(비밀번호 제외, 잠긴 카드 거부)
- 탭 드래프트 저장·세션 복원, 저장 안 한 빈 카드는 draft 처리, 확인 대화상자 `useConfirm` 표준화 + ESC는 최상단 창만 닫기
- 품질 게이트: Vitest 43파일 · 약 420케이스, Playwright E2E, `verify.sh` 릴리스 메타 드리프트 검사

## 🚨 트러블슈팅

### 1️⃣ IndexedDB 스키마 마이그레이션 데이터 손실
* **문제 상황:** Dexie.js 스키마 업그레이드 시 기존 데이터가 유실되는 현상 발생
* **원인 분석:** 인덱스 변경과 데이터 변환이 동시에 이루어지며 트랜잭션 충돌
* **해결 방안:** `upgrade()` 콜백에서 데이터 마이그레이션 로직을 명시적으로 작성하고, 레거시 타입 매핑(`LEGACY_TYPE_MAP`)으로 이전 버전 호환성 확보

### 2️⃣ Smart Paste API 타입 오탐 → 정규식 경로 폐기
* **문제 상황:** URL 1개만 있어도 API 타입으로 감지되는 오탐 발생
* **원인 분석:** Tier 1 정규식 패턴이 URL 존재만으로 API 타입을 판단
* **해결 방안:** curl · 인증 키 · HTTP 메서드+URL 조합이 있을 때만 API로 감지하도록 강화(v1.1.1). 이후에도 패턴 보강 비용이 계속 발생해 v1.2.1에서 정규식 Tier 자체를 제거하고 AI 단일 호출로 전환

### 3️⃣ File System Access API 브라우저 호환성
* **문제 상황:** Firefox에서 `showSaveFilePicker`/`showOpenFilePicker` API 미지원으로 내보내기/가져오기 실패
* **원인 분석:** FSAA는 Chrome/Edge 전용 API
* **해결 방안:** `<input type="file">` + Blob URL 폴백 패턴 구현으로 모든 브라우저 대응

### 4️⃣ 정적 게이트는 전부 통과했는데 Ctrl+F가 아예 동작하지 않음
* **문제 상황:** 타입·린트·빌드·E2E와 리뷰 에이전트 6회가 모두 통과했지만, 브라우저에서 Ctrl+F를 눌러도 반응 없음
* **원인 분석:** 세 결함이 겹쳐 있었음 — ① CodeMirror 6에서 `Mod-F`의 대문자 `F`는 Shift를 의미해 Ctrl+Shift+F에 바인딩됨 ② `view.dom.classList`로 붙인 클래스가 CodeMirror의 className 재계산 때 지워짐 ③ `literal: true` 설정이 검색 패널 commit 과정에서 전달되지 않아 타이핑 순간 기본값으로 복귀
* **해결 방안:** 키를 소문자로 정규화하고, 클래스는 `StateField` + `EditorView.editorAttributes`로 선언, `transactionFilter`로 `literal`을 강제. **라이브러리 소스를 직접 읽고 나서야** 확정된 결함들이라, 이후 라이브러리 통합 기능은 실기 확인 + 소스 확인을 완료 조건으로 설정

### 5️⃣ 바꾸기가 클릭 두 번에 한 건만 반영되고 엉뚱한 행이 바뀜
* **문제 상황:** `sc→cs` 치환 시 다른 행들이 연달아 바뀌고, `sc→scc`는 같은 자리가 반복 치환됨
* **원인 분석:** ① 부모의 `useMemo`가 렌더 중에 자식 ref를 읽어 항상 한 단계 낡은 값 사용 ② 커서를 배열 인덱스로 보관 ③ DOM 요소를 값 일치(`el.value === text`)로 탐색 — 검색에서는 같은 문자열이 여러 곳에 있는 게 기본이라 항상 첫 요소를 집음
* **해결 방안:** 치환 타깃을 state로 끌어올리고, 커서는 `{path, offset}` 위치로, 조회는 `data-search-path` 경로로 변경. 조건부 렌더 위젯은 `useLayoutEffect`로 펼쳐 포커스 이동보다 먼저 반영

### 6️⃣ Dexie 트랜잭션 안에서 WebCrypto를 await → 조기 커밋으로 복구 불가 위험
* **문제 상황:** 암호화 활성화 중 기존 데이터 일괄 암호화는 커밋됐는데 salt 기록이 실패하면, 키를 다시 만들 수 없어 데이터가 영구히 복구 불가능해지는 경로 존재
* **원인 분석:** Dexie 트랜잭션 안에서 Dexie가 아닌 Promise(WebCrypto)를 기다리면 트랜잭션이 먼저 닫힘(`PrematureCommitError`). 앞서 실행된 쓰기는 이미 반영되어 되돌릴 수 없고, 테스트용 fake-indexeddb는 이 위험을 실제보다 작게 보여줌
* **해결 방안:** 암호 연산을 메모리에서 모두 끝낸 뒤 트랜잭션에는 Dexie 호출만 넣는 **compute-then-write 불변식**을 세우고 활성화 과정을 원자화. 쓰기 경로는 실패를 그대로 throw, 표시 경로는 관대하게 흡수하도록 분리

## 💡 회고

서버 없이 브라우저만으로 동작하는 앱을 설계하면서, IndexedDB의 비동기 특성과 스키마 마이그레이션의 복잡성을 깊이 경험했습니다. 특히 Dexie.js의 `useLiveQuery`를 활용한 반응형 데이터 바인딩이 React 상태 관리와 자연스럽게 통합되는 패턴을 확립할 수 있었습니다.

AI 기능은 "API 키 없이도 동작하되, 있으면 더 잘 동작한다"는 목표로 정규식 + AI 2단 구조에서 출발했지만, 정규식 오탐을 막기 위한 패턴 보강이 끝없이 이어지면서 **공유 키 + 멀티 프로바이더 BYOK** 구조로 방향을 바꿨습니다. 같은 목표를 더 적은 유지비로 달성하는 쪽을 택한, 설계를 버릴 줄 아는 경험이었습니다.

찾기/바꾸기를 만들면서 얻은 가장 큰 교훈은 **"코드에 그렇게 쓰여 있다"와 "그렇게 동작한다"는 다르다**는 것입니다. 타입·린트·빌드·E2E와 리뷰 에이전트 6회를 모두 통과한 코드가 브라우저에서는 기능째 죽어 있었고, 원인은 키 문자열 규약·라이브러리의 DOM 재계산·설정 전달 범위처럼 정적 검사가 볼 수 없는 곳에 있었습니다. 보안 쪽에서는 "유출 차단"을 제품 기능으로 내세우는 대신, 운영자조차 평문을 볼 수 없다는 **zero-knowledge만 보증 가능한 가치**로 남겼습니다.
