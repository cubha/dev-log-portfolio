## 🚨 트러블슈팅

### 1️⃣ GitHub Private 레포 커밋 집계 불가
* **문제 상황:** REST Events API(`/users/{username}/events`)는 Private 레포 `PushEvent`에서 `payload.size`, `payload.commits` 필드를 모두 제거함
* **원인 분석:** REST API의 보안 및 프라이버시 정책으로 인한 페이로드 누락
* **해결 방안:** **GitHub GraphQL API**의 `viewer.contributionsCollection`으로 대체하여 Private 포함 정확한 연간 커밋 수 확보

### 2️⃣ Supabase RLS SELECT 정책 무력화
* **문제 상황:** `USING(true)` 정책이 하나라도 존재하면 OR 연산으로 인해 다른 제한 정책이 무효화됨
* **원인 분석:** Supabase(PostgreSQL) RLS의 정책 평가 방식이 다중 정책을 OR 조건으로 합산하기 때문
* **해결 방안:** 공개/비공개 **분리 정책 조합 방식**으로 재설계하여 단일 `USING(true)` 남용 방지 및 권한 제어 강화

### 3️⃣ Framer Motion 신규 카드 미작동
* **문제 상황:** 이미 마운트된 부모 내에 새로 추가된 자식 컴포넌트는 부모의 variant 전파를 받지 못함
* **원인 분석:** React 생명주기와 Framer Motion의 DOM 진입 감지 시점 불일치
* **해결 방안:** 각 카드 컴포넌트에 `initial` / `whileInView`를 **명시적으로 직접 선언**하여 독립적으로 동작하도록 수정

### 4️⃣ Supabase 무료 티어 pause 3회 재발 — HTTP 200을 받고도 멈춤
* **문제 상황:** 무료 티어 프로젝트가 세 번 일시정지됨. 3차는 이틀 전 keep-alive 핑이 HTTP 200이었는데도 발생했고, 유일한 동적 페이지인 Contact만 깨짐
* **원인 분석:** pause 기준은 "7일 무요청"이 아니라 **주간 DB 활동량 임계치**였고, 6일 간격 read 핑 1회로는 부족했음. GitHub Actions의 `*/3` 스케줄도 실제로는 6일 간격으로 돌고 있었음. 2차는 타입 에러로 **한 달간 빌드가 실패**해 대응 코드가 배포조차 되지 않은 것이 원인
* **해결 방안:** write 핑으로 전환(`keep_alive` 테이블 + SECURITY DEFINER RPC), GitHub Actions 매일 + Vercel Cron 매일 이중화로 하루 4회 요청. 핑이 2xx가 아니면 워크플로가 실패해 메일 경보가 오도록 하고, **일부러 pause시키는 chaos test**로 경보를 실측 확인

### 5️⃣ 어드민 배경 선언 70개가 조용히 무시되고 있었음 — 3.5개월
* **문제 상황:** 어드민 화면의 배경색 선언들이 실제로는 렌더되지 않았지만 tsc · eslint · build 어디서도 에러가 없었음
* **원인 분석:** `bg-[var(--surface)]`처럼 채널삼중값 토큰(`50 13% 96%`)을 그대로 소비하면 유효한 색이 아니라 브라우저가 선언을 **조용히 폐기**함. 이 토큰 계열은 문서에 한 건도 없었고, 기존 검사 스크립트의 주석 제외 필터는 `grep -n`이 앞에 줄번호를 붙이는 탓에 아무것도 거르지 못하고 있었음
* **해결 방안:** 12개 파일 64줄을 `hsl(var(--x))` 또는 Tailwind 유틸로 치환하고 누락된 다크 테마 토큰 3종 추가. 채널삼중값 raw 소비를 `:root`에서 토큰명을 자동 수집해 잡는 게이트를 신설하고 필터 결함도 수정

### 6️⃣ RLS 권한상승 취약점 — 로그인만 하면 누구나 쓰기 가능
* **문제 상황:** skills 테이블 쓰기 정책이 `authenticated`만 확인해, 방명록용 GitHub OAuth로 로그인한 누구나 스킬 데이터를 수정·삭제할 수 있었음. 배포 전 보안 검토에서 방명록 좋아요 INSERT가 `user_id`를 검증하지 않아 타인 UUID로 위조 가능한 결함(Critical)도 추가 발견
* **원인 분석:** "로그인한 사용자 = 관리자"라는 암묵 전제 — 방명록에 소셜 로그인을 붙이는 순간 그 전제가 깨졌음
* **해결 방안:** 쓰기 정책을 `profiles.role = 'admin'` 조건으로 강화하고, 방명록 INSERT는 `user_id is null or user_id = auth.uid()`로 제한. Supabase advisor 경고 해소를 확인. keep-alive RPC도 호출 출처 파라미터를 검증하지 않아 **공개 키로 핑을 위장해 장애 기록을 가릴 수 있음**을 발견해 허용값 검증 추가

## 🤖 3-AI 협업 개발 구조
각 AI의 강점을 극대화한 효율적인 개발 파이프라인을 구축하여 프로젝트를 진행했습니다.

- **Claude Code (Controller):** 요구사항 분석, 아키텍처 설계, 프롬프트 작성, 코드 검증
- **Cursor (Implementer):** 실질적인 코드 구현 전담
- **Gemini (Researcher):** 외부 리서치 (라이브러리 비교, 최신 기술 트렌드 조사)
- **이후 운영 단계 (Claude Code 스킬 파이프라인):** `/analyze` → `/braintrust`(다관점 검토) → 구현 → `/ship` 흐름으로 진행. 머지 전 security-auditor · db-schema-reviewer · scope-critic 서브에이전트가 병렬 검토해 실제 Critical 취약점 2건을 잡아냄. 디자인은 Claude Design 시안을 기준 문서로, 검증은 Playwright로 수행

## 💡 회고

3-AI 협업 구조를 처음 도입하며 역할 분리가 명확해질수록 개발 속도와 품질이 극대화되는 것을 체감했습니다. 특히, 프롬프트 설계 능력이 전체 개발 생산성에 직결된다는 점을 깊이 배웠습니다.

Next.js 15의 RSC(React Server Components), Server Action, Middleware 레이어를 실전에서 다루며 서버와 클라이언트 간의 경계 설계의 중요성을 재확인했습니다.

운영 단계에서 가장 오래 살아남은 결함은 모두 **에러 없이 조용히 실패하는 것들**이었습니다. 3.5개월간 무시된 CSS 선언, 한 달간 실패한 빌드, HTTP 200을 받고도 멈춘 데이터베이스가 그랬습니다. 이를 막은 것은 문서에 적은 금지 조항이 아니라 **기계가 돌리는 검사**였습니다 — 토큰 소비 게이트, 실패를 크게 알리는 워크플로, 일부러 장애를 일으켜 보는 실측. 또 "어드민은 디자인 범위 밖"이라는 예외 선언이 결함이 쌓이는 자리가 되고, 입력 검증 없는 모니터링은 위장 가능한 거짓 안전 신호가 된다는 것도 배웠습니다.
