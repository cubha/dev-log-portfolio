# 📟 AgentVitals — Claude Code · Codex 사용량 모니터 (구 Claude Code Gauge)

> **에디터를 떠나지 않고 Claude Code와 Codex의 사용량·Rate Limit·번레이트·토큰 비용을 실시간으로 확인하는 VS Code / Cursor Extension**
> 사이드바의 Claude / Codex 전환으로 두 에이전트를 같은 화면에서 추적합니다. Claude는 공식 API 헤더 + 로컬 `~/.claude` jsonl, Codex는 로컬 `~/.codex` rollout 로그만 읽어 — 프라이빗 API 없이 동작합니다. (이름 변천: *ClaudePulse* → *Claude Code Gauge* → *AgentVitals* · 마켓 ID `cubha.claude-code-gauge` 유지)

## ✨ 핵심 구현 내용

### 1. 🔀 이중 데이터 소스 아키텍처 — 프라이빗 API 0개
사용량을 두 개의 독립 소스로 분리해 수집하는 구조를 설계했습니다.
- **Rate Limit (5h / 7d)**: Anthropic 공식 API의 응답 헤더에서 추출 — poll당 1-토큰 haiku 요청(≈5~10 입력 토큰)으로 쿼터 소모 최소화
- **토큰·비용**: `~/.claude/projects/**/*.jsonl` 로컬 파일 파싱 — 네트워크 호출도, 비공식 API도 없음
- **플랜 티어**: 로컬 credentials에서 `Max 5x` 등 구독 등급을 추가 API 호출 없이 표시
- **스트리밍 중복 제거**: `requestId` + `message.id` 이중 dedup으로 스트리밍 응답 이중 카운트 방지

### 2. 📊 StatusBar · Sidebar · Dashboard 3계층 UI + 예측
같은 데이터를 밀도가 다른 세 표면으로 노출합니다.
- **StatusBar**: `5H 🟦🟦⬜⬜⬜ 28%` / `7D 🟦⬜⬜⬜⬜ 14%` 2개 독립 아이템 — 사용률 임계값(80/90/100%)에 따라 색·배경·폰트가 OK/Warning/Danger/Blocked로 전환
- **Sidebar**: 세션(5h)·주간(7d)·초과사용량 3섹션 + 상태 컬러 진행바, 병목 윈도우(5h/7d) amber 하이라이트
- **Burn Rate / Safe Until**: `%/min` 소비 속도를 세션 경과 시간으로 1차 추정 후 poll 히스토리로 보정 → 5h 쿼터 소진 예상 시각 예측
- **Dashboard Panel**: SESSION·WEEKLY·BURN RATE·SAFE UNTIL 4카드 + 30m/2h/24h 토글 추이 차트

### 3. 💰 토큰·비용 분석 — 오프라인 가격 계산
API 호출 없이 로컬 로그만으로 비용을 산출합니다.
- **LiteLLM 가격 스냅샷 내장**: fable-5 / opus-4.5–4.8 / sonnet-4.5–4.6 / haiku-4.5 모델별 단가를 임베드해 오프라인 계산
- **모델·캐시 효율**: 오늘의 주 모델 칩, 캐시 히트율(`⚡ 72%`)과 절감 비용, 모델별 비용 도넛 차트
- **장기 추적**: 일별 스냅샷을 `globalStorageUri/ccg-history.json`에 영속화 → jsonl 로테이션을 넘겨 월 단위 추이/이번 달 예상 비용 제공

### 4. 🎯 비용 귀속(Attribution) — "정직한 근사" 설계
측정 한계를 숨기지 않고 1급(first-class) 버킷으로 드러내는 패턴을 일관 적용했습니다.
- **Cost by Skill**: Claude Code가 스킬을 stamp하는 구간은 *스킬이 로드된 메인체인 턴*(≈33%)뿐 — 나머지 67%를 숨기지 않고 **"Outside skills"** 버킷으로 노출, 헤더에 `≈ Partial` 배지
- **Cost by Commit (usage×git 회고)**: 커밋은 로그에 기록되지 않으므로 `timestamp + cwd + branch` 근사 조인 — `≈ Approximate` 배지 + 신뢰도 점 + **"Other / Uncommitted"** 버킷, SHA-키 영속화로 30일 로그 윈도우 초과 생존
- **Git Branch ROI**: 모든 jsonl 항목의 `gitBranch` 필드로 브랜치별 Cost·Tokens·Sessions 집계, 비용순 정렬
- **Subagent 분리**: `isSidechain`/`agentId`로 서브에이전트 소비를 메인 세션과 분리 집계

### 5. 🌐 4개 국어 i18n + 실시간 동기화
- 한국어 / English / 日本語 / 中文 — 사이드바 헤더 드롭다운에서 전환 시 라벨·섹션명·에러·번레이트 문자열까지 즉시 갱신
- 사이드바에서 언어 변경 시 Dashboard Panel을 재오픈 없이 extension messaging 브로드캐스트로 실시간 동기화
- 최초 설치 시 `navigator.language` 자동 감지 → `globalState`로 선택 영속화

### 6. 🔀 Codex 통합 — 단일 에이전트에서 "dual-use" 대시보드로 (v0.2.0)
Claude 전용이던 구조를 프로바이더 추상화(`AgentSource`)로 일반화하고, 사이드바 헤더의 Claude / Codex 스위처로 게이지·오늘 비용·모델/캐시 분해·Git 브랜치 ROI·Usage Calendar를 두 에이전트 모두에 제공합니다.
- **Rate Limit 버킷 런타임 생성**: Codex rollout의 `token_count` 이벤트가 싣는 `rate_limits`를 읽되, `primary = 5h`로 하드코딩하지 않고 각 버킷의 `window_minutes`로 판별 — Free 플랜은 **30일 단일 버킷**, 유료 플랜은 5h + 7d (자체 머신 실측으로 2차 자료의 "전 플랜 5h+주간" 기술을 반박)
- **두 기록 경로 분리**: 토큰은 `token_usage_record`(응답 단위 증분, `response_id` dedup), 한도는 `event_msg[token_count]`에서만 — 둘을 합산하면 정확히 2배, `token_count`의 누적값은 컨텍스트 창 채움 로직에 의해 덮어써져 신뢰 불가
- **7일 경과 `.jsonl.zst` 압축본 + `archived_sessions/`** 까지 수집해 오래된 데이터가 조용히 사라지지 않도록 처리
- **없는 데이터는 추측하지 않음**: 스킬 귀속·서브에이전트·MCP처럼 Codex 로그에 없는 지표는 숨기고, 대신 추론 토큰·실제 컨텍스트 창 크기·플랜 배지를 제공. 미설치 / 미로그인 / 세션 없음 3가지 빈 상태를 각각 다른 안내로 분리
- **리브랜딩 제약**: 마켓 ID·설정 네임스페이스(`claudeCodeGauge.*`)는 불변(변경 시 설치수·평점 소실), 표시명만 교체. 마켓 검색이 ID 슬러그를 랭킹에 반영하지 않는다는 실측에 따라 옛 이름을 `keywords`에 보존

### 7. 🧠 세션 컨텍스트 게이지 · Usage Calendar · 비용 탭 통합
- **컨텍스트 사용률 게이지**: 현재 세션이 컨텍스트 창을 얼마나 채웠는지 워크스페이스 단위로 표시, 멀티루트 워크스페이스에서는 세션 선택기 제공. Codex는 로그의 `model_context_window`로 정적 테이블보다 정확하게 산출
- **Usage Calendar 히트맵**: 1년 고정 뷰 + 사이드바 미니 캘린더, MCP 서버별 비용 귀속과 기간 토글
- **Cost by Period**: 흩어져 있던 일별·월별·장기 비용 차트 3개를 탭 하나로 통합(장기 탭 30/90/180일 토글 유지)
- **시각 개편**: 대시보드 카드 17개 → 6개, 모든 차트에 라인 끝 수치 표기, 설명 문장을 상태 마커(Normal / Drop, Under / Over pace, ⚠ price unknown) + 툴팁으로 압축, VS Code 라이트·고대비 테마 실시간 연동

### 8. ⚡ 증분 파싱 · 리프레시 설계
- Codex 경로에도 Claude와 같은 **mtime + offset 증분 캐시**를 도입해 매 리프레시(기본 15초)마다 전체 히스토리를 재파싱하던 비용 제거
- 파일 크기가 같은 다른 파일로 교체(rotate)되는 경우를 파일 선두 비교로 감지해 처음부터 재독
- 스트림 소스(작업 중 계속 쓰이는 로그)에는 디바운스 대신 **즉시 1회 + 고정 주기 스로틀** 적용 — 리프레시 간격을 설정(`usageRefreshIntervalMs`)으로 노출하고 수동 새로고침은 스로틀을 우회

## 🚨 트러블슈팅

### 1️⃣ `spawnSync` git 호출이 Extension Host 이벤트 루프를 블로킹 → 카드 무한 로딩
* **문제 상황:** "Cost by Commit" 카드가 *Collecting data…* 플레이스홀더에서 영영 벗어나지 못하고, 대시보드를 새로고침해도 복구되지 않음
* **원인 분석:** 웹뷰 렌더 경로(무조건 replace)는 정상이었고, **응답 자체가 도착하지 않는 것**이 진짜 원인. `buildRetroSummary`가 git을 **동기**(`spawnSync`)로 호출해 extension-host 이벤트 루프를 막아 RPC 응답이 전달되지 못했고, 활성 세션이 `.jsonl`을 쓸 때마다 빌드가 재트리거되어 루프가 고착됨
* **해결 방안:** GitLogReader를 **완전 비동기화**(`spawnSync` → `execFile` + `await`) + **5s 타임아웃**으로 git이 호스트를 막거나 무한 대기하지 못하게 함. 레코드가 실제 변경될 때만 **debounce·dedup 재빌드**하고 요약을 영속화해 세션 간 즉시 first-paint. 소비처가 0이던 `git log --name-only`를 제거해 대형 레포 `git log` 비용 약 5× 절감

### 2️⃣ 스트리밍 응답 이중 카운트로 토큰·비용 과대 집계
* **문제 상황:** 스트리밍으로 분할 전송되는 응답이 여러 청크로 기록되어 동일 응답이 중복 합산됨
* **원인 분석:** jsonl 한 응답이 streaming chunk 단위로 복수 엔트리를 남겨, 단순 합산 시 토큰·비용이 부풀려짐
* **해결 방안:** `requestId` + `message.id` **이중 dedup** 키로 동일 응답을 한 번만 계상하도록 집계 파이프라인 수정

### 3️⃣ 스킬 비용 귀속이 전체 비용의 ~33%만 커버 → 카드가 전부를 담은 것처럼 오인
* **문제 상황:** Cost by Skill이 `attributionSkill`이 찍힌 턴만 합산해, 표시 비용이 실제 총비용과 크게 어긋남
* **원인 분석:** Claude Code는 *스킬이 활성 로드된 메인체인 턴*에만 스킬을 stamp(≈33%) — 평범한 요청과 스킬 로드 전후 작업(≈67%)이 조용히 사라짐
* **해결 방안:** 미귀속 메인체인 작업(`!isSidechain && !attributionSkill`)을 **"Outside skills" 1급 버킷**으로 노출하고, 점유율을 총합 기준으로 재계산 + `≈ Partial` 배지로 귀속 범위를 명시. 서브에이전트(sidechain) 비용은 버킷에서 제외해 이중 계상 차단

### 4️⃣ 컨텍스트 사용률 게이지가 최대 5배 과대 표시
* **문제 상황:** 사용자 신고 — 세션을 막 시작했는데 컨텍스트 게이지가 36%를 표시
* **원인 분석:** 1M 컨텍스트가 활성화된 모델을 200K 창으로 취급하는 **분모 오분류**(최대 5×)가 주원인. 200K 폴백은 "보수적 기본값"처럼 보였지만 분모를 줄이는 쪽이라 사용률을 부풀리는 방향이었음. 부차적으로 `usage.iterations` 합산과 서브에이전트(`isSidechain`) 레코드 미배제가 겹침
* **해결 방안:** "관측 증명(실제 200K 초과 토큰 관측) + 설정 파일의 `[1m]` 표기" 2단 계단으로 1M 여부를 판정하고 분자·사이드체인 문제를 함께 수정. 실 레코드 38,505건 A/B 재검증으로 9개 워크스페이스 전부 교정 확인. 사용자가 제안한 "repo 드롭다운"은 이 버그를 고치지 못했을 것 — 스코핑은 정상이었고 분모 값 자체가 틀렸음

### 5️⃣ 비용이 실제의 1~2%로 표시 — 모든 게 정상처럼 보이는 $0
* **문제 상황:** 비용 수치가 실사용 대비 1~2% 수준이고, 모델 분해 차트는 거의 쓰지 않는 구모델이 100%를 차지
* **원인 분석:** 가격표에 현행 세대 모델(Opus 5 · Sonnet 5)이 누락되었고, 신규 모델을 잡아야 할 패밀리 폴백은 **한 번도 발화한 적이 없었음** → 대부분의 레코드가 $0으로 계산되는데 에러 없이 정상 화면처럼 보임. 점유율도 비용 기준이라 가격 있는 구모델이 100%로 표시
* **해결 방안:** Claude Code가 로그에 기록하는 모델별 실제 비용에서 단가를 역산해 가격표를 교정하고 fixture로 고정. 가격 미상 모델이 있으면 점유율을 토큰 기준으로 전환 + 해당 행을 `$0.00` 대신 **"price unknown"** 으로 표시 — 측정처럼 보이는 0을 금지

### 6️⃣ Codex 서브에이전트 이력 재생으로 사용량 이중 계상
* **문제 상황:** v0.2.0 출하 후 코드 감사에서, Codex 사용량이 서브에이전트가 있는 세션에서 부풀려질 수 있음을 발견(외부 도구들에서 30~150× 과대 계상 사례 보고)
* **원인 분석:** 서브에이전트는 **자기 rollout 파일**에 부모 세션 이력을 재생하는데, dedup `seen` Set이 파일 함수 로컬이라 파일 하나 안에서만 유효 — 규칙은 맞았지만 **적용 범위(파일 하나 vs 파일 집합)** 가 틀렸음
* **해결 방안:** 전체 파일 집합에 대한 전역 `response_id` dedup 2차 패스 추가(v0.2.1). 같은 릴리스의 보안 검토에서 증분 리더가 append 도중의 미완결 마지막 줄을 건너뛰고 offset을 전진시켜 **영구 소실**시킬 수 있음을 추가 발견 → 마지막 개행 이후는 파싱하지 않고 offset도 그 지점까지만 전진하도록 수정

### 7️⃣ 정리 스크립트가 "미사용"으로 판단한 색을 지워 Fable이 검은 조각으로 출하
* **문제 상황:** 모델 분해 도넛에서 Fable 모델이 검은 조각으로, 막대는 아예 표시되지 않은 채 두 릴리스 연속 출하. 모든 빌드 검사는 초록불
* **원인 분석:** 미사용 CSS 토큰을 검색해 제거하는 정리 작업이 `--c-fable`을 지움 — 차트는 모델명으로 **토큰 이름을 런타임에 조립**해 조회하므로 정적 검색으로는 사용처를 찾을 수 없었음
* **해결 방안:** 색을 복구하고, 코드가 실제로 토큰을 소비하는 방식(TS 쪽 조립 패턴)대로 검사하는 빌드 게이트를 추가해 모델 색 누락을 차단

## 💡 회고

이 프로젝트의 설계 중심은 **"정직한 근사(Honest Approximation)"** 였습니다. 사용량·비용 데이터는 본질적으로 불완전하지만 — 스킬은 33%만 stamp되고, 커밋은 로그에 없으며, 스트리밍은 중복을 만듭니다 — 그 한계를 숨기고 그럴듯한 숫자를 보여주는 대신, 측정되지 않는 부분을 **"Outside skills" · "Other / Uncommitted"** 같은 1급 버킷과 `≈ Partial` / `≈ Approximate` 배지로 명시적으로 드러냈습니다.

가장 값진 교훈은 트러블슈팅 1번에서 나왔습니다. "무한 로딩"의 원인을 렌더 경로에서 찾다 실패하고, 결국 **동기 git 호출이 이벤트 루프를 막아 응답 자체가 출발하지 못한다**는 진짜 원인을 짚어낸 경험은, 증상이 보이는 계층과 결함이 있는 계층이 다를 수 있다는 디버깅 원칙을 다시 새기게 했습니다. 비공식 API 0개·로컬 우선이라는 제약을 끝까지 지키면서도 실사용 가치를 만든 것이 이 프로젝트의 핵심 성취입니다.

Codex 통합 이후의 교훈은 **"규칙이 옳은가"와 "그 규칙이 어디까지 적용되는가"는 별개의 검증**이라는 것입니다. dedup 규칙은 정확히 정의했지만 파일 하나 범위에만 걸려 있었고, 가격 폴백은 존재했지만 한 번도 발화한 적이 없었으며, 색 토큰은 "미사용"으로 보였지만 런타임에 조립되고 있었습니다. 세 사고 모두 테스트는 초록불이었습니다. 그래서 이후로는 게이트를 추가할 때 일부러 깨뜨려 RED를 확인한 뒤 채택하고, 측정처럼 보이는 0 대신 "price unknown"처럼 모르는 것을 모른다고 표시하는 원칙을 Claude와 Codex 양쪽에 똑같이 적용했습니다.
